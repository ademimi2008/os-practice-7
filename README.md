# Практическая работа № 7. Случайный лес (уровень B)

Дисциплина «Машинное обучение». Модель оттока абонентов мобильного оператора на основе случайного леса и анализ того, какие признаки действительно влияют на уход.

> Датасет `churn_synthetic.csv` синтетический: 3000 абонентов, сгенерированы программой. Это не реальные данные О! или другого оператора, названия компаний — только контекст задачи.

## Что внутри

| Файл | Описание |
|---|---|
| `pr7_random_forest.ipynb` | Ноутбук с решением (пункты 1–5 задания) |
| `churn_synthetic.csv` | Данные (положите рядом с ноутбуком, выдаёт преподаватель) |
| `README.md` | Этот файл |

## Что делает ноутбук

1. **GridSearchCV** с `StratifiedKFold(5, shuffle=True, random_state=42)` и `scoring="roc_auc"`. Сетка: `n_estimators` ∈ {100, 300}, `max_depth` ∈ {None, 6, 10}, `min_samples_leaf` ∈ {1, 5, 20}, `max_features` ∈ {"sqrt", 0.5}.
2. **Сравнение на test** настроенной модели и модели по умолчанию по ROC-AUC и F1, с объяснением, почему метрики могут разойтись.
3. **График OOB-оценки** для `n_estimators` ∈ {10, 25, 50, 100, 200, 400} и выбор числа деревьев.
4. **Удаление признаков** по одному, от наименее важного, с ROC-AUC на кросс-валидации (среднее ± std).
5. **Вывод:** какие признаки можно исключить. Различие считается реальным, только если оно больше разброса между фолдами.

Общие условия: `train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)`, `region` и `tariff` кодируются `OneHotEncoder` внутри `Pipeline`. Столбец `subscriber_code` — идентификатор, в признаки не входит.

## Запуск в VS Code (Windows, PowerShell)

1. Откройте папку проекта в VS Code и положите `churn_synthetic.csv` рядом с ноутбуком (имя файла должно совпадать).
2. Создайте и активируйте виртуальное окружение (один раз создать, каждый раз активировать):
   ```
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```
   Если PowerShell ругается на запрет сценариев, один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и повторите активацию. В начале строки терминала должно появиться `(.venv)`.
3. Установите библиотеки (при активном `(.venv)`):
   ```
   pip install numpy pandas matplotlib scikit-learn ipykernel
   ```
   Пакет называется `scikit-learn`, а не `sklearn`.
4. Откройте `pr7_random_forest.ipynb`, справа сверху нажмите **Select Kernel → Python Environments → .venv**.
5. Нажмите **Restart**, затем **Run All**. Подбор параметров занимает 1–5 минут (180 обучений моделей).
6. Проверьте первую строку вывода: должно быть `Загружен churn_synthetic.csv (3000, 13)`. Если написано `ЗАПАСНЫЕ ДАННЫЕ (файл не найден)!`, значит CSV не найден, и результаты сдавать нельзя.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `ModuleNotFoundError: No module named 'numpy'` | Ядро ноутбука не то, где установлены библиотеки. Активируйте `.venv`, выполните `pip install` из шага 3 и выберите ядро `.venv` (шаг 4). Проверка: `import sys; print(sys.executable)` должно показать путь с `.venv` |
| В логе pip `Defaulting to user installation` | `.venv` не активирован, пакеты ушли в глобальный Python |
| Предупреждение про запасные данные | CSV лежит не рядом с ноутбуком или назван иначе |
| Ячейка долго выполняется | Это нормально для GridSearchCV, подождите до 5 минут |

## Чего не делать

- Не менять `random_state=42`, `test_size=0.2` и сетку параметров: они заданы в условии.
- Не подбирать параметры и не выбирать признаки по test: это делается на train с кросс-валидацией, test нужен только для итогового сравнения.
- Не добавлять `subscriber_code` в признаки.
- Не убирать строку про синтетический датасет из отчёта.

## Примечания

- `oob_score_` в sklearn — это accuracy, а не ROC-AUC.
- Важность признаков по impurity смещена в пользу непрерывных признаков и признаков с большим числом значений. Это корреляционная, а не причинная связь.
